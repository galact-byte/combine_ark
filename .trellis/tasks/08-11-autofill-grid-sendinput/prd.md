# 自动填色改用网格识别与 SendInput 注入

## Goal

修复「自动填色跑完但游戏画布全空」：当前用 `pyautogui`（底层 `mouse_event`）向 PC 客户端点击，用户实测**完全无反应**，判定为合成鼠标事件被游戏吞掉（叠加 UIPI 提权拦截可能）。改为 **SendInput 注入 + 启动时请求管理员权限**，并用**截图网格线识别**取代手填 19 个坐标框，让画布定位自动、精确、随分辨率自适应。

## Background / 现状

方案来自研究两个参考项目（JayJokerr 的 arknights-pixel-autofill、Arknights-Painter）后「取其精华去其糟粕」的结论（详见 design.md）。两个病因：

- **① 坐标盲猜（主因）**：`calibration.suggested_layout` 只把写死的 1280×720 参考矩形按比例缩放，从没截图看真实画布位置。种子坐标本身是对的（与参考项目 CONFIG 一致），缺的是「截图识别真实网格线来校正」这一步——非 1280×720 分辨率下纯比例推算整体偏出格子，点击全落格外，故「报完成却全空」。
- **② 点击方式+权限**：`autofill.PyAutoGuiMouse` 用 `pyautogui` → 老式 `mouse_event`，Unity 聚焦后切 Raw Input 直接忽略（游戏外能动、游戏内不动）；游戏常以管理员运行，非管理员注入被 UIPI 拒。用户实测**完全无反应**印证 ②。
- `ui.open_calibration` 让用户手填 19 个数字框，矩形对不准且「看不懂数字没法手调」。
- 已有安全机制需保留/改造：绑定窗口句柄+进程、前台核验、失焦即停、确认弹窗、白格跳过。

## Requirements

### 必须

- R1 **SendInput 双路注入**：新增基于 Win32 `SendInput` 的鼠标驱动替换 `pyautogui`。「双路」＝先发**相对位移**事件喂 Unity Raw Input，再发**绝对坐标**（0..65535 虚拟桌面归一化）校系统光标；`PostMessage` 作兜底路径。滚轮同样走 SendInput。
- R2 **管理员权限**：启动时 `IsUserAnAdmin()` 检测；非管理员则 `ShellExecute(runas)` 以管理员重启并退出当前进程，只重试一次（防 UAC 拒绝后死循环）。
- R3 **网格识别**：截图游戏客户区，以 **BASE 1280×720 居中视口模型**为初始估计定 ROI，在 ROI 内用投影式梯度检测约 25 条等间距网格线，反推精确画布 `Rect` 与每格中心；置信度不足回退视口种子几何并明确提示。
- R4 **校准 UI 重构**：去掉 19 个手填数字框。流程变为「捕获窗口 → 自动截图识别画布 → 截图预览叠加网格/色板框供确认」；用户接受建议值即可，无需读懂数字。
- R5 **F8 急停替代**：填色支持 F8 全局急停，**替代**原「鼠标移左上角」failsafe（相对位移注入会误触发左上角）；保留「停止按钮」和「失焦核验」两条急停。
- R6 **色板滚动改造**：改为多次单刻度滚动 + 每刻度重锚，防 Unity 把一次大滚动只算一格。
- R7 全过程仍绑定校准窗口句柄+进程，每步前核验前台一致，不一致不发送任何输入。
- R8 **色板识别（补：真机发现颜色错）**：用户实测 SendInput 能画了但颜色错——因为色板面板贴右边缘，UI 缩放 90 下面板缩小内收，与按中心缩放的画布不同步，固定比例/锚定画布都会错。改为用已知 40 色精确 RGB 在截图右侧（排除画布区）“认色板”：最近色归类得到色块中心，按色号固定的 col=k%4/row=k//4 最小二乘拟合出色板矩形。两页模型经真机截图确认：顶页色号 1–24（索引 0–23），底页滚到底显示色号 17–40（索引 16–39，偏移 16），面板同屏原地换内容 → 底部色板=顶部矩形，滚轮给足量（over-scroll 自然停在底）。

### 不做（本次范围外）

- 不支持 Android 模拟器 / ADB / 移动端（那是另一个 C# 项目 Dr-hydra 的路子）。
- 不做色板色块的全自动色彩识别（色板仍用视口种子建议值 + 可视确认；画布网格才做自动识别）。
- 不改图像量化/裁切管线。
- 不抄参考项目的功能蔓延：官方分享图导入、跨屏截图导入、算法比例双滑杆、实时缩略预览、更新检查、无边框响应式窗口重构。

## Constraints

- 不硬编码任何文件路径或分辨率；客户区、DPI、截图为运行时输入。
- 校准数据只写当前用户应用数据目录，绝不碰游戏文件。
- 依赖最小化：截图用已在依赖内的 Pillow（`ImageGrab`）；窗口枚举/`SendInput`/`PostMessage`/提权全用 `ctypes`，**不新增 pywin32 或任何第三方库**。
- 仅 Windows；非 Windows 环境下自动化相关模块延迟导入，不阻断导图/图纸功能。

## Acceptance Criteria

- [ ] AC1 网格识别对合成 24×24 网格图（已知偏移/缩放）能反推出画布框与 25 条线位置，误差在容差内（自动化测试）。
- [ ] AC2 坐标归一化函数（屏幕像素→0..65535 虚拟桌面绝对坐标）有单测覆盖边界。
- [ ] AC3 提权决策函数（is_admin + 是否已重试）纯函数可单测，不会死循环。
- [ ] AC4 网格识别置信度不足时回退建议几何且状态栏提示，不静默用错坐标。
- [ ] AC5 校准弹窗不再要求手填 19 个坐标；截图预览可确认。
- [ ] AC6 `python -m pytest -q` 全绿、`python -m compileall -q ark_pixel_helper main.py` 通过。
- [ ] AC7 安全机制到位：确认弹窗、窗口/进程核验、失焦即停、F8 急停（替代左上角 failsafe）、停止按钮、白格跳过。
- [ ] AC8 色板识别对合成色板图能反推顶部色板矩形（误差容忍内）、无色板时返回 None 回退；`calibration_from_capture` 能一张截图同时得出画布与色板并构造合法 Calibration（自动化测试）。

## 已确认决策（来自用户）

- 手动点击时**完全无反应** → 确认病因 ②（事件被吞），SendInput 双路注入+提权为核心修复。
- 网格识别方案由实现方推荐：采用投影式网格线检测 + 视口种子初始估计（见 design.md）。
- 提权方式：**启动时** `ShellExecute(runas)` 请求管理员（弹 UAC）。
- 取舍原则来自参考项目研究：取网格识别/SendInput 双路/提权/视口模型/单刻度滚动/F8 六条，去功能蔓延与 ADB 路线，不新增依赖。
