# 技术设计：导入即手动裁切与细节保留

## 交互边界

图片选择成功后，`PixelHelperApp.import_image()` 不再直接调用转换，而是打开模态 `CropDialog`。对话框以适合窗口大小的缩略图显示完整原图，并覆盖固定 1:1 正方形裁切框。用户拖动框内区域移动位置，拖动四个角调整正方形边长，滚轮围绕指针缩放；`取消` 关闭对话框且不改变当前 `source_image`、`Pattern` 或导入目录状态，`使用此区域` 才提交裁切框。

裁切框内部使用原图像素坐标 `CropBox(left, top, side)` 存储，不从屏幕缩略图反推。缩略图仅是原图与画布坐标之间的无损比例映射。提交后，应用保存原图副本与 `CropBox`，调用转换管线；重新选择“调整裁切”时，读取同一框继续编辑。裁切弹窗右侧另有 24×24 终局预览画布：每次 `_redraw()` 后以当前 CropBox 调用纯转换管线、绘制固定 40 色网格；预览无独立编辑状态，不可作为数据源。

## 图像管线

`ImageOptions` 新增可选 `crop_box`。当该值存在时，`prepare_square()` 首先在原图坐标裁出该严格正方形区域，绕过当前居中裁切及横纵偏移；随后按选择的取样方式缩放为 24×24，并量化至固定 40 色。无 `crop_box` 时保留原有 crop/contain/stretch 行为，以保持测试与旧流程兼容。

“减少杂色”默认从最多 16 色调整为“清晰轮廓”可选策略；初始导图优先保留全部 40 色候选，避免人物的眼睛、脸部高光和局部轮廓被低频色合并。用户仍可主动启用清晰轮廓策略以处理风景或噪点输入。

## 数据契约

```python
@dataclass(frozen=True)
class CropBox:
    left: int
    top: int
    side: int

    def validate_for(image_size: tuple[int, int]) -> None: ...

@dataclass
class ImageOptions:
    crop_box: CropBox | None = None
```

- `CropBox` 必须完全位于原图范围内且 `side > 0`；无效数据抛出 `ValueError`，不改变当前 Pattern。
- `CropDialog` 只在主 tkinter 线程中运行；不涉及游戏窗口或鼠标自动绘制。
- 结果仍为 `Pattern`，因此图纸导出和自动绘制不需要新接口。

## 错误与回滚

原图不可读、缩略图生成失败、框选越界或用户取消时，UI 给出中文状态提示并保留上一张图案。裁切提交后若量化失败，保留旧 Pattern 和已选择的原图/框，允许用户重试。该改动不修改校准或自动化模块。

## 验证策略

- 单元测试 CropBox 的边界校验、原图裁切准确性、取消不提交与重新打开时保留裁切框。
- 用用户提供的竖幅和横幅人像构造离线测试/人工验收：用户分别框住脸和眼睛，预览必须让双眼占据有意义的像素区域。
- 运行完整 pytest、compileall、裁切对话框构建烟雾测试；不运行真实游戏点击。
