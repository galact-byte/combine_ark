# 修复拼豆图像还原效果

## 目标

针对用户实际导入的半身人像，将 24×24、固定 40 色的转换结果从“可见大致颜色”提升为“可一眼辨认人物脸部、发型和眼睛”的像素图；自动绘制、固定调色板和本地处理安全边界保持不变。

## 已确认的事实

- 复现输入：`132221493_p0.png`，1664×2432 的竖幅近景人像；主体脸部位于图像中上区域，特征为深灰发、浅肤色、紫色眼睛和头饰。
- 当前导出图为完整图像裁切后直接平滑缩小、再量化；脸与眼睛在 24×24 中被零散暗色和过度压色淹没，用户无法认可其相似度。
- 第二复现输入：`17.png`，10919×5043 的横幅插画；人物位于画面右侧、双眼和花束是识别重点。当前居中裁切落在头发/花束之间，未保住双眼；同时“最多 16 色”压缩削弱了花朵与眼睛的高饱和特征。
- 游戏限制不可变：24×24 网格和活动固定 40 色；不得增加外部模型、在线服务或替换游戏颜色。

## 范围内需求

- 用户从文件选择器选中图片后，必须先进入类似“更换头像”的可视化裁切确认页，再返回主界面；不得未经用户确认就直接量化转换。
- 裁切确认页提供可视化、可手动操作的正方形裁切器：用户在原图缩略预览上直接拖动裁切框、调整大小/缩放并移动位置；确认的框选区域是后续 24×24 转换的唯一图像来源。
- 裁切确认页必须同时显示会随裁切框实时更新的 24×24、游戏固定 40 色预览，让用户以最终拼豆效果而非原图缩略图判断脸部和眼睛是否被保住。
- 可视化裁切器应让用户能优先框选角色脸部、双眼和发型，而非保留无关服装、背景或花束边缘；不得依赖人脸识别模型或自动猜测作为必要条件。
- 在量化前增强局部明暗分离与适度色彩信息，优先保留眼睛、脸部亮区、发型轮廓等对人物辨识最有价值的像素。
- 默认转换不再把低频颜色简单压到 16 种主色；用户可在“清晰轮廓”与“更多颜色细节”之间选择，并实时对比 24×24 预览。
- 现有“横向/纵向”裁切滑块不再作为主要构图方式；可保留为快捷微调，但不能替代可视化框选。
- 继续严格输出 40 色调色板中的色号，`Pattern`、导出图纸和自动绘制数据流不得改变。

## 非目标

- 不承诺将任意照片在 24×24 中无损还原，也不引入 AI 人脸识别、联网处理或任意新颜色。
- 不改变游戏窗口校准、鼠标点击安全、图纸导出或夏日 UI 的既有行为。

## 验收标准

- [ ] 用户选择任一图片后会先看到裁切确认页；拖动、缩放裁切框时，实时 24×24/40 色预览同步变化。取消时不得改变当前图案；确认后转换只使用直接框选的正方形区域，且该区域在重新打开裁切器时可被看见和继续调整。
- [ ] 对 `132221493_p0.png`，用户框选头部后，结果中脸部和双眼形成可辨认的明暗/紫色特征，而不是被杂乱暗色块淹没。
- [ ] 对 `17.png`，用户框选右侧角色的脸和双眼后，结果优先保留双眼和发型轮廓而非无关背景。
- [ ] 用户可选择至少两种清晰命名的细节策略，并能立即对比它们的 24×24 效果。
- [ ] 所有转换结果严格为 24×24，且每格颜色均为固定 40 色调色板之一。
- [ ] 原有图片导入、单格编辑、图纸导出与自动绘制测试仍然通过。

## 当前开放问题

需要通过离线实验确认最适合该类竖幅人像的默认主体裁切比例和细节保留策略。
